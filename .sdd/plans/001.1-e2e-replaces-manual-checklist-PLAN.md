# Plan amendment 001.1: E2E replaces the manual checklist

Status: APPROVED 2026-10-20
Amends: .sdd/plans/001-house-and-conditional-schedules-PLAN.md (approved 2026-10-19)
Open questions: 1 (spec 002, not yet written, must take the 21 end-user scenarios as requirements)

## What changes
1. **D1 Test strategy.** The automated part is unchanged: stdlib `unittest` in `tests/` with HA stubs. The manual checklist part is replaced: the WP3, WP4 and WP5 checks are automated end-to-end (E2E) tests from spec 002, run against the user's HA test container. Following SDD rule T2, the E2E suite runs only when the user asks.
2. **Section 4, "Manual checklist on the HA test container"** becomes "E2E checks on the HA test container (spec 002)". The text in brackets after the old heading ("user deploys `beta`, restarts, then runs the listed calls in Developer Tools and dashboard steps; each work package lists its checks with expected results") becomes: "the spec 002 suite runs the checks against the deployed `beta` on the test container, when the user asks". The three areas it lists stay the same: services and schemas (R2, R3, R11, R12, R13); options flow (R6, R18); cards (R14, R15, R16). The checks are the 21 end-user scenarios in tasks amendment 001.1, written from the point of view of the household user, the installer and the automation author.
3. **Section 5.** In the Outputs of WP3, WP4 and WP5, "manual checklist" becomes "E2E checks (spec 002)". In the WP3 Scope, "checklist includes a `copy_day` carry-over check" becomes "E2E checks include a `copy_day` carry-over check (scenario 8)".
4. **Section 6, Risks.**
   - "Stubs drift from real HA": its mitigation now reads "every work package's E2E checks run on the real test container".
   - "Manual checks depend on the test container" becomes "E2E checks depend on the test container and on spec 002". Mitigation: WP1 and WP2 are fully covered by unit tests. The WP3 to WP5 checks are pending, not passed, until the spec 002 suite runs them.
   - "Making `room` optional" and "Options flow default blocks clearing": "WP3 checklist" becomes "WP3 E2E checks".
5. **Dependency.** WP3 to WP5 are verified only after spec 002 delivers the E2E suite. Spec 002 must take the 21 end-user scenarios as requirements.

Requirement coverage is unchanged.

## Why
User decision 2026-10-20: build E2E testing first and test spec 001 that way. A manual checklist left 23 checks to be run by hand; E2E tests are repeatable.

## Supersedes
In plan 001: the manual checklist part of D1; the section 4 manual checklist heading and its bracketed procedure; "manual checklist" in the WP3 to WP5 Outputs; "checklist" in the WP3 Scope; and the four section 6 mitigations named above. Nothing else changes.
