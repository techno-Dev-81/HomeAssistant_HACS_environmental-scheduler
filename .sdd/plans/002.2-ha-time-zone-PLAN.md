# Plan amendment 002.2: tests use HA's time zone

Status: APPROVED 2026-10-21
Amends: .sdd/plans/002-e2e-testing-PLAN.md (approved 2026-10-20), after amendment 002.1

## What changes
1. **Section 1, Runner.** After the env checks and before Playwright starts, `run.sh` reads HA's `time_zone` from `GET <HA_URL>/api/config` and exports it as `TZ`.
   - The token is read from the environment inside `python3 -I`. It is never on a command line and never printed.
   - Only the zone name is printed ("HA time zone: <zone>").
   - If the zone cannot be read, `run.sh` exits 2 before Playwright starts.
2. **Section 2, Results folder.** Run folder names use HA's local time.
3. **Section 6, "Blocks near midnight".** The time window is built from the local clock, which is now in HA's time zone, so "now" matches the integration's local time.

## Why
User decision 2026-10-21. The Claude session container runs in UTC, while the HA test instance runs in Europe/London (one hour ahead today). Blocks placed around the container's "now" had already ended in HA's time, so scenarios 6 and 11 failed (runs 20261021-084308 and 084424). The user chose to take the time zone from HA itself, with nothing for the user to configure.

## Supersedes
Plan 002 section 1 (Runner steps), section 2 (Results folder naming) and section 6 (the clock used by the time window). Everything else is unchanged.
