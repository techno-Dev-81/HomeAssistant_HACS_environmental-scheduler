# Tasks amendment 001.1: E2E replaces the manual checklists

Status: APPROVED 2026-10-20
Amends: .sdd/tasks/001-house-and-conditional-schedules-TASKS.md (approved 2026-10-19)
Implements: .sdd/plans/001-house-and-conditional-schedules-PLAN.md as amended by .sdd/plans/001.1-e2e-replaces-manual-checklist-PLAN.md
Open questions: 1 (spec 002, not yet written, must take the 21 user scenarios below as requirements)

## What changes
1. The manual checklists of T3.8, T4.6 and T5.3 are replaced by the 21 end-user scenarios below. Each scenario becomes at least one automated end-to-end (E2E) test from spec 002 (E2E testing), run against the HA test container. Under SDD rule T2 ("Run a full E2E suite only when the user asks"), the suite runs only when the user asks.
2. The scenarios say what the user does and what they should see. They cover the same checks as the old checklist items, which are shown in the last column for traceability only.
3. New task T4.7 lists four user decisions that cannot be tested. The user accepted (a) to (c) on 2026-10-20 as provisional, to review on trial. They are recorded in the Evidence of tasks 001 T4.1, T4.3 and T4.4. Item (d) was found during implementation review on 2026-10-20 and is not recorded in tasks 001.
4. Two old checks are dropped by user decision 2026-10-20: the house schedule leaves a room named "House" unchanged (old T3.8 h), and the editor lists a room named "House" separately (old T4.6 b). With the house as its own entity, the user does not expect a room named "House". The code that keeps them separate is unchanged, and spec 001 R2 still requires it; it is not checked end to end.
5. The "spec 002 E2E suite" dependency is external: it is not a task in this file. Spec 002 must list the 21 scenarios as requirements.

- the **household user**, on the dashboard cards;

## Coverage

## Why
User decision 2026-10-20: build E2E testing first and test spec 001 that way, instead of a manual checklist. E2E tests are written from the end user's point of view. A manual checklist left 23 checks to be run by hand; E2E tests are repeatable. The four T4.7 items are preferences, not pass or fail checks, so they stay with the user.
