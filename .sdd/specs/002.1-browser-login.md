# Spec amendment 002.1: browser login with username and password

Status: APPROVED 2026-10-20
Amends: .sdd/specs/002-e2e-testing.md (approved 2026-10-20)

## What changes
1. **Gate 4 (first sentence only) and section 6.** The rest of gate 4 stands unchanged: Claude never opens the env file, only the runner reads it; the runner starts only when the file holds `E2E_CONFIRM_TEST_INSTANCE=yes`; the target is a test instance with weekly backups.
   - The browser logs in through the HA login page with the username and password of an HA admin user, as a user would.
   - The admin token is used only for engine tests and setup through the WebSocket API.
   - The env file holds `HA_USERNAME` and `HA_PASSWORD` in addition to the address, token and confirmation line.
   - The section 6 "E2E run" row's "Requires" cell becomes: "Env file present with HA address, admin token, `HA_USERNAME`, `HA_PASSWORD` and confirmation line".
2. **R2.**
   - The runner reads the HA address, admin token, `HA_USERNAME`, `HA_PASSWORD` and `E2E_CONFIRM_TEST_INSTANCE` from the git-ignored `tests/e2e/.env`.
   - If any is missing, or the confirmation is not `yes`, it stops before any test. It prints which item is missing (never a value) and exits non-zero.
3. **R10d.** Results never hold the admin token or the password. Both are replaced with `[redacted]` in every results file, trace archives and the HTML report's embedded data included, and the run then checks that neither remains. A file that still holds one is deleted, and the run is marked failed.

## Why
User decision 2026-10-20 (plan 002, decision D1): the browser tests log in as a user would, not by injecting the token.

## Supersedes
- In spec 002: the first sentence of gate 4 ("The runner uses the long-lived access token of an HA admin user, held with the HA address in a git-ignored env file"), the section 6 "E2E run" row's "Requires" cell, R2 and R10d.
- Everything else in spec 002 is unchanged.
